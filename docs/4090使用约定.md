# GPU 使用约定（4090 / 本机 / 免费 T4）

按《选题 1–5 的学习资料与 12 周计划》的要求整理，并结合本机实测更新。

## 一、谁能用卡

| 选题 | 用卡方式 | 建议时段 |
|---|---|---|
| 1 | 只做推理，单次几分钟到几十分钟 | 白天，随用随跑 |
| 2、3 | 少量语言模型判断，其余在 CPU | 白天；也可以用免费的 T4，不占 4090 |
| 4 | 向量模型加少量语言模型判断，主要吃内存 | 白天；表连接和训练轻量模型在 CPU 上 |
| 5 | 反复微调，单次可达数小时 | 夜间和周末整段占用 |

选题二属于"用卡很低"的一档：**GPU 上只跑语言模型判断，其余全部在 CPU 上完成。**

## 二、四条约定

1. **共享一张排期表。** 长于一小时的任务提前登记（见文末表格）；跑之前先看一眼有没有人在用：

   ```powershell
   nvidia-smi --query-gpu=name,memory.total,memory.used,utilization.gpu --format=csv
   ```

2. **所有语言模型的输入输出都缓存到磁盘，同样的输入不算第二遍。**
   本项目已实现：`data/<网络>/llm_cache/` 逐次生成落盘，配合 `PROMPT_VERSION`
   版本号（改 Prompt 自动失效旧缓存）；`batch_seed` 固定，同一输入必然复现同一结果。

3. **调试用小数据、小模型，在本机或免费 T4 上完成；4090 只跑正式实验。**
   本机的正确用法是：验证管道、跑最小网络（ASIA）、看趋势；正式的全网络结果放 4090。

4. **长任务放 tmux 里运行，日志落盘，并定期保存检查点，被打断后能续跑。**

   ```bash
   tmux new -s prior            # 新建会话
   python scripts/run_llm_prior.py --network CHILD --mode both
   # Ctrl+B 然后 D 分离；tmux attach -t prior 重新接回
   ```

   Windows 本机没有 tmux，等价做法是后台进程 + 日志重定向：

   ```powershell
   Start-Process -FilePath 'D:\Anaconda\envs\llm_causal_fs\python.exe' `
       -ArgumentList 'scripts\run_llm_prior.py','--network','CHILD','--mode','both' `
       -WindowStyle Hidden -RedirectStandardOutput 'logs\child.out.log' `
       -RedirectStandardError 'logs\child.err.log'
   ```

   断点续跑不需要额外机制：脚本每完成一次生成就落一次盘，重跑自动跳过已完成部分。

## 三、本机能力实测（RTX 3060 Laptop，6GB）

| 模型 | 是否可跑 | 实测 |
|---|---|---|
| Qwen3-4B-Instruct-2507 4bit | 可以 | 真实名约 0.6 次/秒，匿名约 0.2 次/秒 |
| Qwen/Qwen3-8B 4bit | 可以但不实用 | 加载 33 秒、显存 6002 MiB；短跑约 48 秒/条，长跑因显存分页退化到 1.75 小时/条 |

按 48 秒/条估算 8B 的全量成本：ASIA 约 1.9 小时、CHILD 12.7 小时、
INSURANCE 23 小时、ALARM 44 小时、HAILFINDER 102 小时。**大网络必须用 4090 或 T4。**

注意：4bit 量化不支持分层到 CPU，因此 8B 必须显式 `--device-map gpu0`；
用默认的 `auto` 会判定装不下并直接报错。

## 四、vLLM 的平台限制与替代方案

vLLM 官方只提供 Linux 发行版（实测：`pip download vllm --platform win_amd64`
返回 `from versions: none`，而 `--platform manylinux2014_x86_64` 能列出全部版本）。
其官方硬件要求是 **compute capability ≥ 7.5，且明确点名支持 T4**。三条路：

| 方案 | 可行性 | 说明 |
|---|---|---|
| 原生 Windows | 不可行 | 无对应发行版 |
| WSL2 + Ubuntu | 可行 | GPU 直通正常（驱动 546.30 足够）；装完 `pip install vllm` 即可 |
| 免费 T4（Colab / Kaggle） | 可行，推荐 | 16GB 显存；8B 用 AWQ/GPTQ 4bit（约 5GB）舒适，纯 fp16 放不下 |
| 实验室 4090（Linux） | 可行 | 24GB，可跑 8B 且能开批处理 |

Colab / Kaggle 免费额度的三个坑：
Colab 单次会话约 12 小时且闲置会断、虚拟机重置后本地文件全丢（缓存要写回 Drive）；
Kaggle 每周 30 小时额度、单次最长 12 小时，且必须手动打开 Internet 开关才能下模型。

### 4.1 Colab 环境的可复现做法（踩坑后确定的规范）

Colab 每次会话都是新虚拟机，环境必须能一条命令重建，并且**版本必须固定**。
统一用 `scripts/setup_colab.sh`：

| 做法 | 原因 |
|---|---|
| 建隔离虚拟环境（virtualenv，不用 `python -m venv`） | Colab 的 `venv` 常因 ensurepip 失败；且隔离能绕开 Colab 预装包（google-adk、cudf、cuml 等）与 vLLM 的依赖冲突 |
| 固定 `vllm==0.31.0` | 不固定版本会随镜像滚动更新而变化，出问题无法复现 |
| 驱动 < 580 时把 torch 换成 CUDA 12.1 版 | CUDA 13 的 torch（`+cu130`）要求驱动 ≥580；Colab 的 T4 常低于此，表现为 vLLM `Engine core initialization failed` |
| 推理时加 `--enforce-eager` | T4 是 Turing（sm_75），CUDA 图捕获容易在引擎初始化阶段失败 |
| 验证时要真的分配一次显存 | 只看 `torch.cuda.is_available()` 不能暴露驱动不匹配，必须 `torch.zeros(3,3,device='cuda')` 试一下 |

仓库同步用 git（`git clone` / `git pull`），不打压缩包：压缩包在不同平台间传递
容易出现路径分隔符问题（PowerShell 5.1 的 `Compress-Archive` 会写出反斜杠条目名，
Linux 会把整串当成一个文件名），版本也容易与仓库不一致。

## 五、算力需求（按选题二的研究定义）

选题二的描述文档写明"算力需求极低，CPU 加一张小卡"，
先验抽取用的是"中小模型"。因此本机 + 免费 T4 足以覆盖全部实验；
4090 的价值主要在批处理吞吐（vLLM 连续批处理对小样本量判断这类短输出任务提升显著）。
