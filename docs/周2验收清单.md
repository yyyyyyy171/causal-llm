文档对周 2 的要求：在 5 个 OpenML 数据集上，用同一套评测框架（固定划分、固定下游模型）
跑通互信息、mRMR、树模型重要性、L1、前向选择五种方法。

验收产出：**一个可复用的评测框架**，加一张**"方法 × 数据集"的结果表**。
选题 1、2、4 后面直接复用。

## 框架怎么做到"固定划分、固定下游模型"

1. **固定划分落盘。** 60% 训练 / 20% 验证 / 20% 测试，
   划分索引写进 `data/openml/<数据集>_splits.json` 并进版本库。
   任何人任何时候跑，划分完全一致——不是靠"记得设种子"，而是划分本身就是文件。
   验证集留给选题 1、2、4 后面调参用，测试集只在最后评估。
2. **固定下游模型。** 标准化 + 逻辑回归，对所有数据集、所有方法完全一致。
   换下游模型（选题 1 要换成 TabPFN / XGBoost）只需改配置里的
   `downstream_model` 字段，评测流程不动。
3. **统一预处理。** 数值列中位数填补；类别列 one-hot（缺失单独算一类），
   编码器只在训练集上拟合，避免信息泄漏。
   列类型以 OpenML 自己的元数据为准并落盘成 `*_schema.json`
   ——sklearn 会把取值很少的数值列推断成类别类型，直接信 pandas 的 dtype 会把整数特征错误地展开。
4. **返回完整排序而不是前 k 个。** 五个方法都返回全部特征的重要性顺序，
   所以同一份结果可以被不同预算重复使用，正好对应选题 1 的 10% / 25% / 50% 实验。

## 数据集选型与体检

用 `data_id` 固定版本，避免同名数据集的不同版本混淆。

| 数据集 | OpenML id | 样本数 | 特征数（编码后） | 类别数 | 多数类基线 | 全部特征准确率 |
|---|---|---|---|---|---|---|
| credit-g | 31 | 1000 | 61 | 2 | 0.7000 | 0.7400 |
| segment | 36 | 2310 | 19 | 7 | 0.1667 | 0.9459 |
| kr-vs-kp | 3 | 3196 | 73 | 2 | 0.5484 | 0.9641 |
| spambase | 44 | 4601 | 57 | 2 | 0.5993 | 0.9218 |
| ionosphere | 59 | 351 | 34 | 2 | 0.6901 | 0.8451 |

选型覆盖了混合类型（credit-g）、多分类（segment）、全类别特征（kr-vs-kp）、
较大规模（spambase）、小样本（ionosphere），并且全部特征数都大于 primary_k=10，
避免主表出现"选定特征数 = 全部特征"的退化行。

框架里加了数据集体检：报告多数类基线，并在全特征准确率等于 1.0 时告警。
**steel-plates-fault（OpenML 1504）就是这样被剔除的**——那个版本的特征是匿名的
V1…V33，全特征准确率 1.0000，属于退化版本或标签泄漏，不能用。

## 五种方法

| 方法 | 实现要点 |
|---|---|
| 互信息 | `mutual_info_classif`，逐特征打分 |
| mRMR | 互信息贪心：相关性减去与已选特征的平均冗余；冗余矩阵用 `mutual_info_regression` 一行一次算出，p 次调用而不是 p² 次 |
| 树模型重要性 | 随机森林 300 棵树的不纯度重要性 |
| L1 | L1 逻辑回归系数绝对值；多分类用 One-vs-Rest（liblinear 本身不支持多分类） |
| 前向选择 | `SequentialFeatureSelector`，在训练集上 3 折交叉验证，目标函数为准确率 |

## 三个值得写进报告的观察

1. **10 个特征常常够用，甚至更好。** credit-g 上 L1 用 10 个特征拿到 0.7600，
   比全部 61 个特征的 0.7400 还高；segment 上 L1 的 0.9502 也高于全特征的 0.9459。
   这说明特征选择确实有空间，选题 1 要回答的"特征选择对基础模型还有没有用"在这个框架里可以直接接着做。
2. **方法之间的排序随数据集变化。** credit-g 上 L1 最好（0.7600），
   segment 上也是 L1（0.9502），kr-vs-kp 上是树模型重要性（0.9453），
   spambase 上是前向选择（0.8990），ionosphere 上是互信息与前向选择（0.8592）。
   没有哪个方法在所有数据集上占优——这正是后面需要"按模型与数据自适应选特征"的理由。
3. **数据集必须先体检。** 多数类基线是必要的参照：credit-g 的全特征准确率 0.7400
   只比多数类 0.7000 高 4 个百分点，这类数据集上的方法差异要谨慎解读。

## 怎么用（选题 1、2、4 复用）

```powershell
# 换数据集：改 configs/feature_selection.json 的 datasets
# 换下游模型：改 downstream_model（或先在 src/fs/evaluate.py 的 DOWNSTREAM_MODELS 里注册）
# 只跑一部分：命令行覆盖即可
python scripts\run_fs_benchmark.py --datasets spambase,segment --methods l1,forward_selection
```

代码里直接调用：

```python
from src.fs.data import prepare
from src.fs.methods import METHODS

bundle = prepare("spambase", 44, seed=20261012)
ranking = METHODS["mrmr"](bundle["matrix"][bundle["splits"]["train"]],
                          bundle["y"][bundle["splits"]["train"]], 20261012)
top_half = ranking[: len(ranking) // 2]   # 50% 预算
```
